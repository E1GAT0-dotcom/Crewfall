# SPEC.md — Crewfall (working title)

This is the design document. `docs/CONVENTIONS.md` holds the working rules; this file holds *what* to build. Where this document gives a number, it is a default that lives in a config file and is adjustable in the settings screen unless marked fixed.

---

## 1. What this is

A single-player social deduction game in a browser. The player is one of 6–15 crew members on a ship or station. One or more are impostors. Crew win by finishing tasks or voting out every impostor; impostors win by killing until they match the crew count or by letting a critical sabotage run out. Every other character is a scripted bot with its own eyes, memory, suspicions, personality, and voice. Meetings are text chat: the player types, bots respond to the player and argue with each other.

The bots are the product. Everything else exists so the bots have somewhere to be convincing.

## 2. Non-goals for v1

- Online or local multiplayer of any kind.
- Accounts, saves, leaderboards, unlockable cosmetics.
- Bot dialogue generated by a language model or any API.
- Touch controls or mobile layout (keyboard + mouse only).
- Voice chat, cameras/security feeds, admin table, vitals, extra roles (Engineer, Scientist, Shapeshifter, etc.). These are candidates for v2.

## 3. Platform and stack

- Runs locally in Chrome or Edge on Windows. Launched by `play.bat`.
- TypeScript + Vite + Phaser 3 + Vitest.
- Target: steady 60 fps on a mid-range PC. Base canvas 1280×720, scaled to the window.
- Fully offline.

## 4. Rules of the game

### 4.1 Roles
- **Crew**: complete tasks, find the impostor(s).
- **Impostor**: kill crew, sabotage, avoid ejection. Sees other impostors marked in red. Has a fake task list that looks identical to a real one.
- The player can be either. Assignment is random, weighted by the impostor count setting.

### 4.2 Round flow
1. Settings screen → Start.
2. Everyone spawns in the central room (Cafeteria-equivalent) with the emergency button.
3. Free play: tasks, movement, kills, sabotage.
4. A body report or emergency button call freezes everything and opens the Meeting.
5. Meeting: discussion (chat) → voting → result (eject, tie, or skip).
6. Back to free play. Repeat until a win condition.
7. Win/lose screen showing who the impostors were, then back to settings.

### 4.3 Win conditions
- **Crew wins**: all tasks complete, or all impostors ejected.
- **Impostor wins**: living impostors ≥ living crew, or a critical sabotage (Reactor, O2) countdown reaches zero.
- Ejection of the last impostor ends the game immediately.

### 4.4 Meeting rules
- Emergency button: 1 use per player per game (setting), unusable during a sabotage.
- Reporting a body: any living player within report range of a body.
- Discussion phase: chat open, voting closed. Default 15 s.
- Voting phase: chat still open, voting open. Default 60 s. Ends early when all living players have voted.
- Votes: one per living player. Skip is an option. Most votes is ejected; tie = nobody. Confirm-ejects setting shows "X was / was not an impostor" (default on).
- Dead players are silent in meetings. Ghosts can still move and do tasks after the meeting (crew ghosts help finish tasks).
- Bodies are removed after a meeting.

### 4.5 Vision
- Crew vision radius 1.0×, impostor 1.5× (settings). Vision is blocked by walls.
- Lights sabotage reduces crew vision to 0.25×. Impostors unaffected.
- Bots use the same vision rules as the player. What a bot cannot see, it does not know.

### 4.6 Kill rules
- Kill range: short (~one character width), medium, long (setting; default short).
- Kill cooldown default 30 s; starts at 10 s at round start and after each meeting.
- Killing leaves a body that stays until reported.

## 5. Player controls

- Move: WASD or arrow keys.
- Use / interact: E or Space (tasks, emergency button, sabotage panels, doors).
- Report body: R.
- Kill (impostor): Q.
- Vent (impostor): V. While in a vent, arrow keys move between connected vents.
- Sabotage map (impostor): T.
- Full map: Tab (hold).
- Chat in meetings: Enter focuses the text box; Enter sends; Esc unfocuses.
- Pause / settings: Esc.
- Debug overlay: F3.

Mouse is used for menus, minigames, voting, and chat.

## 6. Maps

### 6.1 The three maps
| Map (working names) | Size | Player cap | Impostors (default / max) | Built in |
|---|---|---|---|---|
| Outpost | small | 6 | 1 / 1 | Phase 6 |
| Kestrel | medium | 10 | 2 / 2 | Phase 1 |
| Foundry | large | 15 | 3 / 3 | Phase 6 |

Names are placeholders; Greg may rename. Layouts must be original — not The Skeld, Mira HQ, Polus, or Airship.

### 6.2 Layout requirements (all maps)
- A loop structure: at least two distinct routes between any pair of rooms, so bots and impostors have real choices.
- 1–2 dead-end rooms where kills are tempting.
- One central spawn room with the emergency button.
- Every room has at least one task spot. Room count: Outpost ~8, Kestrel ~12, Foundry ~18.
- Vent networks of 2–3 connected vents each, 2–4 networks per map.
- Sabotage panels spread across the map: Lights, Reactor (two panels in one room, or two rooms for Foundry), O2 (two panels in different rooms), Comms. Door groups on most rooms.
- Corridors long enough that "I saw them heading toward X" is meaningful.
- Room names are generic ship/station names (Electrical, Medbay, Storage, Engine, Reactor, Comms, Navigation, Cafeteria, Security, Weapons, Shields, Admin, O2, Greenhouse, Lab, Cargo, Workshop, Bridge, etc.).

### 6.3 Map data format
Maps are JSON in `assets/maps/<name>.json`. Contents:
- Map name, size class, player cap, impostor defaults.
- Tile layer(s) for floor/walls (tile size fixed at 32 px) and a collision layer.
- Rooms: name, polygon or rectangle bounds. Every walkable tile belongs to exactly one room or "Corridor <n>".
- Spawn point(s).
- Emergency button position.
- Task spots: id, task type, position, room, and for multi-stage tasks, the stage order.
- Vents: id, position, room, network id.
- Sabotage panels: type, position(s), room(s).
- Door groups: room, door tile positions.
- Navigation graph: nodes with positions and room membership, edges with lengths. May be generated from the collision layer at load time and cached; either way it must be drawable in the debug overlay.

Changing a map JSON must not require code changes.

## 7. Tasks

### 7.1 v1 task types (8)
| Task | Kind | Where | Notes |
|---|---|---|---|
| Fix Wiring | Common, multi-stage (3 panels) | 3 rooms | Match colored wires; each panel is a stage. |
| Swipe Card | Common | Admin | Drag speed matters; too fast/slow fails and retries. |
| Upload Data | Long, two-stage | Room A then Admin | Progress bar with a fake stall. |
| Fuel Engines | Long, two-stage | Storage then Engine(s) | Hold to fill; bots stand here a long time. |
| Clear Asteroids | Short, **visual** | Weapons | Click targets; a turret animation is visible to nearby players. |
| Empty Chute | Short, **visual** | Storage / O2 | Hold lever; debris visibly ejects. |
| Align Dish | Short | Comms / Nav | Drag to a target angle. |
| Calibrate Power | Short | Electrical | Timing click on a moving marker. |

"Common" tasks are given to every crew member. Others are drawn per player from the settings (default 1 long, 2 short).

### 7.2 Behavior
- Task list panel on the HUD (toggleable) shows own tasks and completion.
- Task bar shows total crew progress (setting: always / meetings only / never; default always).
- Visual tasks play an animation any nearby player or bot can witness. Witnessing clears suspicion on that player (§9.7). Impostors cannot trigger visual animations even while faking.
- Bots do tasks by walking to the spot and standing there for the task's expected duration (with randomness). Bots never open a minigame UI.
- Minigames open in a modal panel; the player is frozen while it's open; closing is instant. Being killed while in a task closes it.

## 8. Impostor toolkit (player as impostor)

- **Kill**: §4.6. Kill button lights up when a target is in range.
- **Vent**: enter/exit at any vent; move between vents in the network with arrows. Bots that see a vent used log it as certain evidence (§9.7).
- **Sabotage** (T opens the map with buttons; one active at a time; cooldown 30 s after fix):
  - **Lights** — crew vision to 0.25× until the panel switches are flipped (Electrical).
  - **Reactor** — 45 s countdown (60 s on Foundry). Fixed by holding hands on two panels simultaneously for 3 s. Bots can fill both slots; player + bot works too. Reaching zero = impostor win.
  - **O2** — 45 s countdown. Two keypad panels in different rooms; each needs a code entered. Reaching zero = impostor win.
  - **Comms** — hides task list, task bar, and disables task interaction until fixed at the Comms panel. No countdown.
- **Doors**: close a room's doors for 10 s; per-room cooldown 30 s. Usable during other sabotages.
- Fake task list looks identical to a real one; faking at a spot shows the "using" pose.

## 9. Bots

### 9.1 Design goals
- A bot's every accusation, alibi, and vote traces back to something it actually saw, heard in a meeting, or reasoned from. The debug overlay must be able to explain any decision.
- Bots must be fooled by good play and must punish bad play. A player who kills in front of a bot loses. A player who builds an alibi survives.
- Different games feel different: personalities and evidence produce different meetings from the same events.
- All bot code is pure TypeScript, seeded, headless-testable (docs/CONVENTIONS.md).

### 9.2 Architecture
Each bot = Perception → Memory → Social model (suspicion + trust) → Decision layer (goals, movement, kill/sabotage choices) → Voice (chat + voting). Layers communicate through plain data; each is unit-testable alone.

### 9.3 Perception
Every tick, each bot records **sightings** for everything in its vision (same rules as the player, including walls and lights):
- who, where (room + position), when (tick),
- context flags: alone / with [names], doing a task at spot X, doing a **visual** task, entering/exiting a vent, standing near a body, **witnessed a kill** (saw the kill animation), heading toward room Y.
- Also: bodies seen, sabotage alarms heard (global), doors closing (local).

### 9.4 Memory
- A per-bot sightings log with timestamps.
- Recall accuracy by difficulty (§9.12): easy bots may misremember the room or blur the timing; hard bots are exact.
- Public knowledge: everything said in meetings (claims) is stored by every living bot as a **claim** (who said it, what it asserts: "I was in Medbay," "I saw Red in Electrical," "Blue was with me").
- Contradiction detection: a claim that conflicts with a bot's own sightings (same window, different room / different companion) produces a **contradiction** record, which is both evidence (§9.7) and dialogue fuel (§9.9).
- Bots do not remember beyond a configurable number of meetings (default 3; hard: unlimited).

### 9.5 Crew bot behavior
- **Task routing**: pick the next task by nearest-first with a randomness factor; complete all tasks then wander/help.
- **Buddying**: personality-driven tendency to travel with another player. Buddies generate mutual alibis.
- **Bodies**: report on sight, with a personality-based delay (0–3 s). Some personalities pause and look around first (records more sightings).
- **Sabotage response**: the nearest N bots head to fix (N = 2 for two-panel sabotages, otherwise 1–2); others continue tasks or go to a safe group.
- **Fear**: if a bot's top suspect is nearby and no one else is, it walks away toward populated rooms.
- **Emergency button**: a bot calls a meeting only when it has certain evidence (witnessed kill or vent) and no body to report, and hasn't used its meeting.
- Crew ghosts keep doing tasks.

### 9.6 Impostor bot behavior
- **Faking tasks**: goes to task spots and stands for a plausible duration. Never fakes a visual task (bots know this is a tell; on easy they sometimes fake it anyway and get caught).
- **Target selection**: prefers a target that is alone, has no recent witnesses nearby, and (on hard) whoever is most suspicious of the impostor.
- **Kill decision**: only when nobody else is in the impostor's vision, cooldown is ready, and there is an exit (vent or corridor) that doesn't lead into witnesses. Adds a hesitation delay by personality.
- **After a kill**: vent away, or walk away and start a task elsewhere. On hard, sometimes self-reports.
- **Sabotage timing**: uses Lights when suspicion on itself is rising and a kill is wanted; uses Reactor/O2 to split the group, especially when crew tasks are nearly complete; closes doors to isolate a target.
- **Lying**: an alibi is its real route with the kill window swapped for a nearby room it actually passed. Lies are never wildly implausible.
- **Accusing**: accuses whoever it saw alone near the body's room, or whoever is accusing it. On hard, builds a frame across meetings.
- **Two impostors**: don't accuse each other; one may pile on if the other is doomed (hard).
- **Hard mode**: avoids being alone with the player, tracks who has seen it where, and avoids contradicting its own earlier claims.

### 9.7 Suspicion model
Each bot holds `suspicion[target]` from 0 to 100 for every other player, and `trust[other]` from 0 to 1 for every other player (starts 0.5). All weights below are defaults in a config file.

| Evidence | Change |
|---|---|
| Witnessed a kill by target | set to 100 (certain) |
| Saw target use a vent | set to 100 (certain) |
| Target seen leaving the body's room within 20 s before the report | +35 |
| Target was the last person seen with the victim | +30 |
| Target's claim contradicts my sighting | +40 |
| Target accused by a bot I trust | +15 × trust |
| Target accused by the player | +10 (personality-scaled) |
| Target self-reported a body | +10 |
| Target has been shadowing me for 15+ s | +10 |
| Target voted to eject someone who turned out to be crew | +10 (after confirm) |
| Target was continuously with me during the kill window | −40 |
| I saw target do a **visual** task | set to 0 for the rest of the game (cleared) |
| Target was ejected and confirmed impostor | removed from play |
| Each meeting, non-certain evidence decays | −5 |

Trust rises when another player's claims match my sightings and falls on contradictions. Certain evidence (100) never decays.

Thresholds (personality-adjusted): accuse in chat at ≥ 50; vote for the top suspect at ≥ 40, otherwise skip; followers vote with the current majority if their own top is < 40.

Impostor bots run the same model to know who is onto them, but vote strategically (§9.11).

### 9.8 Personalities
Assigned randomly per game, with names and colors. Each personality is a set of multipliers over the defaults.

| Personality | Talks | Follows majority | Accuse threshold | Report delay | Buddies | When accused |
|---|---|---|---|---|---|---|
| Aggressive | a lot | low | 35 | 0 s | rarely | counter-accuses |
| Analyst | medium | low | 55 | 1 s | sometimes | gives full route with times |
| Follower | medium | high | 60 | 2 s | often | defers to majority |
| Quiet | little | medium | 65 | 1 s | sometimes | short denial, states one fact |
| Nervous | a lot | high | 40 | 3 s | often | over-explains, sometimes suspicious-sounding |
| Joker | medium | medium | 50 | 1 s | rarely | deflects with a joke, then a real alibi |

Every bot has a name (short, pronounceable, distinct first letters) and one of 15 colors. The player's name is chosen on the settings screen.

### 9.9 Meeting chat generation
- **Turn scheduler**: at most one bot message every 1.5–3 s; bots respond to a player message within 2–5 s; per-bot message caps per meeting by talkativeness; bots don't all speak at once. If the player says nothing, bots carry the conversation among themselves.
- **Intents** (each with template families): open (react to report/meeting), state alibi, accuse (with reason), corroborate someone's alibi, contradict a claim ("that's not true, I saw you in Electrical"), question someone ("where were you?"), defend self, deflect, suggest skip, follow ("I'm with Red on this"), react to a vote result, react to an ejection (correct / wrong).
- **Templates** live in `src/chat/templates/` as data with slots: `{name}`, `{room}`, `{other}`, `{time_ago}`, `{task}`. At least 6 variants per intent per personality style; no template repeats within a single meeting; casual, short, lowercase-friendly, like real players type. Typos are not simulated.
- **Content is evidence-driven**: an accusation template is only used when the bot has an evidence record to fill it. The strongest evidence picks the wording ("I SAW them vent" vs "they were near Electrical right before").
- **Conversation state** per meeting: who has been accused, by whom, claims made, current vote leaning. Bots reference it ("two people already said Medbay, one of them is lying").
- Dead bots don't speak. Bots don't reveal impostor status; impostor bots never slip in text.

### 9.10 Parsing the player's chat
- Recognize: player names and colors (fuzzy, case-insensitive), room names, and intents: accuse ("it's X", "X vented", "vote X", "X is sus"), alibi ("I was in X", "I was with X"), question ("where were you X?", "X?"), corroborate ("X was with me"), skip ("skip", "no info"), and sightings ("I saw X in Y").
- The player's claims are stored as claims like any bot's. Bots catch the player lying the same way they catch each other (contradictions), and corroborate when their sightings match.
- Unrecognized input gets a personality-appropriate generic response ("what?", "ok…", "say what you mean") and does not change suspicion.
- Questions aimed at a specific bot get an answer from that bot within 2–5 s.

### 9.11 Voting
- Crew bot: vote top suspect if ≥ threshold, else skip; followers follow the majority; analysts refuse to vote on weak evidence in early meetings.
- Impostor bot: never votes its partner; if it is the current majority target, votes for its loudest accuser; otherwise votes with the majority on any crew member; skips when a skip would keep the game going in its favor (crew count low).
- Bots vote at varying times through the voting phase, not all at once, and may change their vote once if new evidence appears in chat.

### 9.12 Difficulty
| | Easy | Normal | Hard |
|---|---|---|---|
| Memory accuracy | 70% | 90% | 100% |
| Memory span (meetings) | 2 | 3 | unlimited |
| Impostor bot faking | sloppy, sometimes fakes visual tasks | good | perfect, avoids visual spots |
| Impostor kill caution | kills only when fully alone | normal | tracks witnesses, frames players, self-reports |
| Crew cross-checking claims | rarely | usually | always |
| Sabotage response | slow | normal | fast and coordinated |
| Targeting the player | random | normal | prioritizes the player when the player is onto it |

### 9.13 Debug overlay (F3) and headless simulator
- F3 shows: FPS, game seed, tick; per bot: current goal, path, personality, role (revealed in debug only), last 5 sightings, suspicion values toward every player, last chat intent used, "why I voted" explanation from the last meeting. Also draws the nav graph and vision radii.
- `npm run sim -- --games 200 --map kestrel --difficulty normal` runs full games headless with all-bot lobbies and prints crew/impostor win rate, average game length, average meetings, ejection accuracy. This is the balancing tool. Target on normal: crew win rate between 35% and 65%.

### 9.14 Tests
Unit tests for: suspicion updates and decay, contradiction detection, visual-task clearing, personality thresholds, template selection with no repeats, the player-chat parser (a table of phrases → expected intent), impostor alibi construction, voting rules. Scenario tests that run scripted mini-games with a seed and assert bot conclusions ("bot A witnessed a kill by B → A accuses B in the next meeting and votes B").

## 10. Meeting UI

- Grid of player tiles: color, name, alive/dead state, "I voted" marker, and vote markers under each tile after votes lock (or immediately if anonymous votes are off — default off).
- Timer at top showing phase and seconds left.
- Chat panel on the right: scrolling log, text box, Enter to send. Messages show sender color and name.
- Vote by clicking a tile then confirming; Skip button; own vote can be changed until the timer ends.
- Result screen: "X was ejected. X was / was not an impostor." (or "No one was ejected") with the eject animation, then return to play.
- Dead player view: can read chat but not type; tiles shown grayed.

## 11. Assets

### 11.1 Characters ("units")
- Original design. Must not read as the Among Us bean. Requirements: compact, one strong silhouette, readable at 64×64, a clearly visible visor/face area, a color region that covers most of the body, and a small distinguishing accessory slot (unused in v1).
- Sprite frames 64×64 px. Sheets per animation: idle (4 frames), walk (8), use/task (4), vent-in (6), vent-out (6), kill-victim (8), dead (1), ghost (4), eject (12). Two layers per frame: **base** (grayscale, tinted at runtime to the player color) and **detail** (fixed colors: visor, accents, shadows). This lets 15 colors come from one sheet.
- Death state is non-gory: a deactivated unit — cracked visor, slumped, small sparks. Kill animation is stylized.
- `assets/sprites/manifest.json` maps logical names (`unit.base.walk`, `unit.detail.walk`, `map.kestrel.tiles`, `task.wiring.panel`, …) to files, frame size, frame count, and frame rate. Game code loads sprites only through the manifest.
- Phase 1–6 use a simple placeholder unit that already follows the format. Phase 7 replaces it with the detailed final art. Replacing any sheet with a file of the same name and dimensions must require no code changes.

### 11.2 Sounds
- `assets/sounds/manifest.json` maps event names to files with default volume: `footstep`, `task_open`, `task_complete`, `kill`, `report`, `meeting_call`, `vote_cast`, `eject`, `sabotage_alarm`, `sabotage_fixed`, `vent_in`, `vent_out`, `door_close`, `button_click`, `win`, `lose`, `chat_message`, `ambient_loop`.
- Placeholder sounds are generated by a script (`npm run gen-sounds`) as short synthesized `.wav` files. Replacing a file with the same name (wav, ogg, or mp3 — manifest lists the extension) requires no code changes.
- Master/music/effects volume in settings.

## 14. Phases and done tests

Each phase ends with Greg play-testing. No phase starts without approval.

**Phase 1 — Skeleton.** Repo, tooling, folder layout, `play.bat`, docs skeleton. Kestrel map as JSON with collision, rooms, spawn, nav graph. Player walks with WASD, collides with walls, camera follows. Tab map. Placeholder unit sprite already in the two-layer manifest format. F3 shows FPS, position, room name, nav graph.
*Done test:* Greg double-clicks `play.bat`, walks into every room without passing through a wall, sees the room name update, holds Tab to see the map. `npm test` passes with at least map-loading tests.

**Phase 2 — Core loop.** Settings screen (Kestrel only, players/impostors/difficulty selectable). Bots spawn, walk between task spots, "do" tasks. Role assignment. Kill, bodies, report, emergency button. Meeting screen with timer, chat box (bots use a tiny generic template set), voting (bots vote randomly or skip). Ejection, task bar, all four win/lose conditions except sabotage, win/lose screen, replay. Seeded RNG in place. F3 per-bot goal and path.
*Done test:* Greg plays 3 games as crew and 1 as impostor; reaches every ending; no console errors.

**Phase 3 — Bot brains.** All of §9. Headless simulator. Full test suite for bots and parser.
*Done test:* Greg plays 5 games. In F3 he can see that every accusation matches a sighting. Typing an accusation changes the accused bot's response and other bots' suspicion visibly. Impostor bots produce plausible alibis. `npm run sim` on normal reports a crew win rate between 35% and 65%.

**Phase 4 — Impostor toolkit.** All of §8 for the player, and bot responses to each sabotage. Impostor bots use the toolkit per §9.6.
*Done test:* Each sabotage can be triggered and fixed; bots arrive to fix; Reactor/O2 reaching zero ends the game; doors trap a bot; venting in front of a bot gets Greg voted out.

**Phase 5 — Task minigames.** All 8 tasks in §7 with minigame UIs, task list panel, visual task animations witnessed by bots.
*Done test:* Greg completes every task type; doing a visual task in front of a bot clears that bot's suspicion of him in F3.

**Phase 6 — Maps.** Outpost and Foundry. Map picker. Caps and impostor defaults per map. Bots and simulator work on all three.
*Done test:* Full games on each map; `npm run sim` on each map within the target win-rate band.

**Phase 7 — Art, sound, polish.** Final detailed unit sprites and all animations per §11.1. Sound manifest with generated placeholders, all events wired. Complete settings screen (§12). Difficulty tuning from simulator data. `docs/HOW-TO-PLAY.md`. Pause menu. Any bug list from earlier phases closed.
*Done test:* Greg swaps one sprite sheet and one sound file with same-named replacements and the game picks them up; a fresh player can learn the game from HOW-TO-PLAY.md alone.
